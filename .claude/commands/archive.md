# /archive

Read `config/stack.md`. This command does not require an external tool role for its core vault operations. Do not assume any specific product.

A project is being closed out. Move it from `1-Areas/<Area>/projects/` to `1-Areas/<Area>/archive/`, preserve git history via `git mv`, update any wikilinks pointing at the old location, and let the auto-index hook regenerate the Area's `_index.md`.

This is a one-way move. The project is done. Confirm before mutating anything.

## What to do

### Phase 1: Identify the target

1. **Resolve the argument.**
   - If a project name or path was passed, match it against folders directly under `1-Areas/*/projects/`. Loose match: "team-training", "Team Training", and "areaname/team-training" should all resolve.
   - If no argument, list all folders under `1-Areas/*/projects/` grouped by Area and ask which one.
   - If the argument matches a single `.md` file at the top level of `projects/` (a project that's just one note, not a folder), that's also valid.
   - If multiple matches, list them and ask which one.

2. **Validate the source.**
   - Source must be inside `1-Areas/<Area>/projects/`. Reject anything in `ongoing/`, `sources/`, `0-Inbox/`, `2-Resources/`, or already in `archive/`.
   - If the source doesn't exist, stop and say so.

3. **Compute the destination.** Same Area, swap `projects/` for `archive/`. If a folder or file with the same name already exists at the destination, ask whether to merge, rename, or abort.

### Phase 2: Confirm

Show exactly what's about to happen. Format:

```
Archiving:
  from: 1-Areas/<Area>/projects/<name>/
  to:   1-Areas/<Area>/archive/<name>/

Contents: <N files, total size>
Last modified: <date>
Inbound wikilinks: <count> (will sweep in Phase 4)

Proceed?
```

Wait for approval. Do not proceed on a maybe.

### Phase 3: Move with git

Use `git mv` so history is preserved as a rename rather than a delete + add:

```bash
git mv "1-Areas/<Area>/projects/<name>" "1-Areas/<Area>/archive/<name>"
```

For a single-file project, `git mv` works the same way on the `.md` file.

If `git mv` fails (uncommitted changes inside the project, etc.), stop and report. Don't fall back to `mv`, as losing history is worse than a failed archive.

### Phase 4: Wikilink sweep

Grep the vault for references to the old path. Three patterns to check:

1. **Wikilinks by filename:** `[[<project-name>]]` and `[[<project-name>|...]]`, which resolve by filename across the vault, so they keep working after the move. Don't rewrite these.
2. **Markdown links with the old path:** `](1-Areas/<Area>/projects/<name>` or `](./projects/<name>` from inside the same Area. These break. Rewrite them to the new `archive/` path.
3. **Plain-text path mentions:** `1-Areas/<Area>/projects/<name>` in prose. Rewrite the ones that are plainly live references; leave the ambiguous or historical ones alone and list them.

Apply the clear reference rewrites (categories 2 and 3 where the mention is plainly a live reference) and report them as a list; the Phase 2 confirmation already announced this sweep, and the fixes are what keep the approved move from breaking links. Leave ambiguous prose mentions (historical record vs live reference) untouched and list them for the user to call. Use `Edit`, not Bash, so the auto-commit hook captures everything in one commit chain.

### Phase 5: Regenerate the index

The auto-index hook only fires on `Write`/`Edit`/`MultiEdit`, not on `git mv`. Trigger it by overwriting the Area's `_index.md` with the auto-marker stub, and the hook will then regenerate the structural index against the new folder contents.

```
# <Area>: Index

<!-- AUTO-INDEX: regenerated by hook -->
```

Use `Write` for this. The PostToolUse hooks will regenerate the index and commit the move + wikilink edits + index in one go.

If the Area's `_index.md` is hand-curated (no auto-marker, more than ~200 chars of real content), don't overwrite it. Note that it needs a manual touch-up and move on.

### Phase 6: Report

One short summary:

```
Archived <name> → 1-Areas/<Area>/archive/<name>/
Wikilinks updated: <N>
Index regenerated: <yes/no>
Commit: <short SHA>
```

## Don't

- Don't archive anything outside `1-Areas/<Area>/projects/`.
- Don't use `mv` or `rm`, always `git mv` so history is preserved.
- Don't rewrite filename-style wikilinks (`[[name]]`), which resolve by filename and survive the move.
- Don't silently overwrite a hand-curated `_index.md`.
- Don't archive without confirmation. The move breaks path links until the sweep repairs them, and whether the project is actually finished is the user's call, not the system's.
